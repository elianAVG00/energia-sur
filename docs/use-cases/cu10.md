# CU10 - Supervise automatic source refresh

- **Source / status:** P, CU10 in the [source key](README.md); **implemented, verified and
  archived** under
  [U24](decisions.md#u24---cu10-source-supervision-decisions-and-propose-authorization)
  and the `supervise-source-refresh-cu10` OpenSpec change (BUILD 1 backend + BUILD 2
  frontend); archived as
  [`2026-11-13-supervise-source-refresh-cu10`](../../openspec/changes/archive/2026-11-13-supervise-source-refresh-cu10/proposal.md).
  Shared [SR03](shared-rules.md#sr03---provenance-and-uncertainty),
  [SR05](shared-rules.md#sr05---automatic-public-data-acquisition) apply.
- **Actor:** administrator.
- **Preconditions:** approved administrator authorization (U24), the two existing ENRE
  sources enabled, and the automatic acquisition infrastructure.

## Main flow

1. Administrator consults the most recent source updates and errors.
2. Administrator requests a retry for a source when needed.
3. Administrator adjusts acquisition intervals for enabled sources.
4. Automatic acquisition continues; status reflects actual outcomes.

## Alternatives

- Source failure, concurrent retry or invalid interval: U24 fixes 409 on a busy source,
  422 on an unsupported interval and preservation of the last valid data (Q22 resolved
  for the supervised scope).
- Unauthorized administrative access: U24 fixes server-side 401/403 checks and a
  controlled CLI promotion (Q21 resolved for the CU10 scope).
- This is not manual entry of public outage/work data or arbitrary source enabling; Q22
  backoff and per-source enable/disable remain out of scope.

## Local rules and dependencies

- **CU10-R1 (P):** administrator views updates/errors, retries acquisition and adjusts
  intervals for enabled sources; public data loading is automatic.
- Dependencies: official-source research, scheduler/connectors, persistence and the

## Verifiable scenario candidates

### CU10-S01 - Inspect update outcomes [ORACLE APPROVED (U24)]
**Trace:** CU10-R1; [SR03](shared-rules.md#sr03---provenance-and-uncertainty),
[SR05](shared-rules.md#sr05---automatic-public-data-acquisition).
**Given** an authorized administrator and synthetic successful/failed source runs,
**When** status is consulted, **Then** actual update/error information is shown without
treating a failed attempt as a successful refresh; last attempt, outcome, last success,
error and interval are derived from the existing fetch-run and snapshot records.

### CU10-S02 - Retry and adjust interval [ORACLE APPROVED (U24)]
**Trace:** CU10-R1; [Q22](decisions.md#q22).
**Given** an enabled source and authorized administrator, **When** a retry and a
supported interval adjustment are requested, **Then** a busy source returns 409 without
queueing, an unsupported interval returns 422, a stale configuration version returns
409, and valid changes apply at the next scheduler cycle (5/10/15/30/60 minutes).

### CU10-S03 - Non-administrator request [ORACLE APPROVED (U24)]
**Trace:** CU10-R1; [Q21](decisions.md#q21).
**Given** a visitor or non-administrator account, **When** it requests administrative
retry or configuration, **Then** the server rejects it (401 unauthenticated, 403
non-admin) regardless of any client-supplied role, and no privileged change occurs.
