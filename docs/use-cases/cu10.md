# CU10 - Supervise automatic source refresh

- **Source / status:** P, CU10 in the [source key](README.md); PLANNED implementation,
  accepted U06 documentary baseline, not implemented. Shared [SR03](shared-rules.md#sr03---provenance-and-uncertainty),
  [SR05](shared-rules.md#sr05---automatic-public-data-acquisition) apply.
- **Actor:** administrator.
- **Preconditions:** approved administrator authorization, enabled official sources
  and automatic acquisition infrastructure, none supplied by the liveness scaffold.

## Main flow

1. Administrator consults the most recent source updates and errors.
2. Administrator requests a retry for a source when needed.
3. Administrator adjusts acquisition intervals for enabled sources.
4. Automatic acquisition continues; status reflects actual outcomes.

## Alternatives

- Source failure, concurrent retry or invalid interval: precise policy TBD Q04/Q22.
- Unauthorized administrative access: action checks require Q21.
- This is not manual entry of public outage/work data or arbitrary source enabling.

## Local rules and dependencies

- **CU10-R1 (P):** administrator views updates/errors, retries acquisition and adjusts
  intervals for enabled sources; public data loading is automatic.
- Dependencies: official-source research, scheduler/connectors, persistence and
  approved admin/auth design; [Q04](decisions.md#q04), [Q21](decisions.md#q21),
  [Q22](decisions.md#q22); Q00. Feeds CU01-CU03; no backend health dependency proves it.

## Verifiable scenario candidates

### CU10-S01 - Inspect update outcomes [PLANNED; semantics TBD]
**Trace:** CU10-R1; [SR03](shared-rules.md#sr03---provenance-and-uncertainty),
[SR05](shared-rules.md#sr05---automatic-public-data-acquisition).
**Given** an authorized administrator and synthetic successful/failed source runs,
**When** status is consulted, **Then** actual update/error information is shown
without treating a failed attempt as a successful refresh. Exact fields await Q04/Q21.

### CU10-S02 - Retry and adjust interval [PLANNED; oracle BLOCKED/TBD]
**Trace:** CU10-R1; [Q22](decisions.md#q22).
**Given** an enabled source and authorized administrator, **When** a retry and a
supported interval adjustment are requested, **Then** automatic acquisition follows
the approved retry/interval policy. Bounds, backoff and concurrency remain TBD.

### CU10-S03 - Non-administrator request [REVIEW; mechanism TBD]
**Trace:** CU10-R1; [Q21](decisions.md#q21).
**Given** a visitor or non-administrator account, **When** it requests administrative
retry or configuration, **Then** it cannot perform unauthorized administration.
The precise role assignment, action checks and error contract require Q21.
