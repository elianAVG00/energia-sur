# CU01 - Query current outages in an area

- **Source / status:** P, CU01 and product summary in the [source key](README.md);
  PLANNED implementation under the accepted U06 documentary baseline; not implemented. Shared [SR01](shared-rules.md#sr01---public-access),
  [SR03](shared-rules.md#sr03---provenance-and-uncertainty) apply.
- **Actor:** visitor or account holder.
- **Preconditions:** a supported address, device location or locality is supplied;
  public-source coverage and matching are defined before implementation.

## Main flow

1. Actor chooses address, device location or locality and supplies the input.
2. System resolves the area, using GeoRef as address assistance where applicable.
3. System queries automatically acquired public outage information for that area.
4. System displays reported outages with source and update date.

## Alternatives

- Ambiguous input, device-location denial or empty results: exact UX TBD Q01/Q02.
- Failed/stale public source: preserve uncertainty; fallback/threshold TBD Q04/Q07.
- No inference that absent reports mean uninterrupted service.

## Local rules and dependencies

- **CU01-R1 (P):** address, device location and locality are proposed query modes.
- **CU01-R2 (P):** results concern reported current outages in the selected area,
  not a guarantee of real-time service at an individual meter.
- Dependencies: GeoRef/location mapping, CU10 public acquisition, official feed
  validation; no account dependency. [Q01](decisions.md#q01), [Q02](decisions.md#q02),
  [Q04](decisions.md#q04), [Q07](decisions.md#q07); global Q00.

## Verifiable scenario candidates

### CU01-S01 - Query without an account [PLANNED; matching TBD]
**Trace:** CU01-R1/R2; [SR01](shared-rules.md#sr01---public-access),
[SR03](shared-rules.md#sr03---provenance-and-uncertainty).
**Given** a visitor and a synthetic supported area with a known official-source record,
**When** the visitor queries that area, **Then** the matching reported outage, source
and update date are visible without sign-in. Exact matching is blocked by Q01/Q04.

### CU01-S02 - Device location unavailable [BLOCKED/TBD]
**Trace:** CU01-R1; [Q02](decisions.md#q02).
**Given** denied device-location permission, **When** the actor chooses that mode,
**Then** the outcome follows the explicitly approved fallback policy. Its expected
response is not yet defined; no automatic permission/fallback choice is implied.

### CU01-S03 - Refresh unavailable [REVIEW; fallback TBD]
**Trace:** [SR03](shared-rules.md#sr03---provenance-and-uncertainty), [Q07](decisions.md#q07).
**Given** the official source cannot refresh, **When** the area is queried,
**Then** no successful fresh update or outage-free status is invented; the exact
stale/error presentation requires Q04/Q07 approval.
