# CU04 - Manage personal addresses and meters

- **Source / status:** P, CU04 in the [source key](README.md); PLANNED implementation,
  accepted U06 documentary baseline, not implemented. Shared [SR02](shared-rules.md#sr02---account-bound-personal-information),
  [SR04](shared-rules.md#sr04---user-supplied-personal-evidence) apply.
- **Actor:** account holder.
- **Preconditions:** an approved account/ownership model and personal-record
  persistence; no auth or database integration exists by virtue of this fiche.

## Main flow

1. Actor supplies a personal address and meter information.
2. System saves the association to that account using the approved identity model.
3. Actor consults or modifies the saved information.
4. Saved addresses/meters can be associated with later queries and personal records.

## Alternatives

- Ambiguous address, duplicate/changed meter association: policy TBD Q08.
- Modification affecting existing records: lifecycle TBD Q09; deletion is not
  silently included as an approved destructive action.

## Local rules and dependencies

- **CU04-R1 (P):** save/modify personal addresses and meters for queries, readings,
  bills and interruptions; cardinality and identity details are unresolved.
- Dependencies: account/auth, PostgreSQL integration and identity/lifecycle decisions;
  GeoRef as an address aid, not proof of ownership. [Q03](decisions.md#q03),
  [Q08](decisions.md#q08), [Q09](decisions.md#q09); Q00.
- CU09 needs only the account-owned domicile registration/list/selection slice,
  with stable identity and display address, not meters or the full CU04 editing/
  deletion scope. Its proposed delivery boundary needs [design review](../../openspec/changes/record-cu09-interruption-diary/design.md).

## Verifiable scenario candidates

### CU04-S01 - Save an address and meter [PLANNED; identity TBD]
**Trace:** CU04-R1; [SR02](shared-rules.md#sr02---account-bound-personal-information).
**Given** an authenticated synthetic account and valid address/meter input,
**When** the actor saves them, **Then** the association can be consulted for that
account and selected for later personal records. Exact identity rules await Q03/Q08.

### CU04-S02 - Modify linked information [BLOCKED/TBD]
**Trace:** CU04-R1; [Q08](decisions.md#q08), [Q09](decisions.md#q09).
**Given** a meter/address with linked history, **When** the actor changes its details,
**Then** the result follows the approved association/history policy. No cascade,
reassignment or history deletion rule is currently approved.

### CU04-S03 - Cross-account access [REVIEW; mechanism TBD]
**Trace:** [SR02](shared-rules.md#sr02---account-bound-personal-information),
[Q03](decisions.md#q03).
**Given** two unrelated synthetic accounts, **When** one requests the other's
personal address or meter, **Then** private records are not exposed. Exact access
checks/error semantics require an approved ownership/auth design.
