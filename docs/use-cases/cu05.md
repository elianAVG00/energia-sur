# CU05 - Record a meter reading

- **Status:** CLOSED / ARCHIVED (2026-11-13). Manual readings, private photos and OCR are implemented; the red-fraction contract conflict is resolved and the canonical [meter-readings specification](../../openspec/specs/meter-readings/spec.md) has 21 requirements / 44 scenarios. U13 supersedes the U06 photo-required/no-OCR CU05 baseline; see the [archived proposal](../../openspec/changes/archive/2026-11-13-record-cu05-meter-readings/proposal.md).
- **Actor / preconditions:** account holder with an owned CU04 meter and authorized access. [SR02](shared-rules.md#sr02---account-bound-personal-information) and [SR04](shared-rules.md#sr04---user-supplied-personal-evidence) apply.

## Main flow

1. Select the owned meter; enter a reading date no later than today, a time and nonnegative integer accumulated kWh. Treatment of a future time on today remains unresolved.
2. Optionally attach one JPG/PNG/WebP photo up to 5 MB and request OCR. A reliable result is an editable suggestion, not a saved reading.
3. Review and explicitly confirm the final value; the system incorporates it in the meter's history, newest first.
4. The owner can edit the value, date and photo but cannot delete the reading; the stable meter ID is retained.

## Rules and alternatives

- **CU05-R1 (U13):** confirm before saving; no confirmed history mutation before confirmation. Photo is optional; see [Q11](decisions.md#q11) for private volume storage and residual lifecycle decisions.
- **CU05-R2 (U13, D05–D07):** warn but allow decreases; store UTC seconds, display Buenos Aires time, block duplicate instants per meter. Comparison details and rollover remain [Q10](decisions.md#q10); physical replacement is excluded.
- **CU05-R3 (latest BUILD instruction, definitive 2026-11-13 resolution):** OCR is opt-in, targets kWh digits and masks clearly separable red fractional digits, suggesting only the integer value; it abstains when the fraction/integer boundary is uncertain. Detection is heuristic, so a fractional digit whose colour is ambiguous, faded or indistinguishable from the integer digits may remain undetected ([resolution](decisions.md#cu05-red-fraction-contract-resolution-2026-11-13)); no absolute exclusion guarantee is claimed, and a suggestion never enters history without explicit manual review and confirmation. Ambiguous or failed OCR shows “No pudimos identificar con seguridad la lectura del medidor. Intentá subir una fotografía más clara o ingresá manualmente el valor en kWh”. Manual entry remains available. No independent blur detector. The endpoint invokes Tesseract on suitable crops; a suggestion can still be wrong and must be checked.
- D01–D13 approve local Tesseract and manual crop; the OCR security and resource limits were implemented and verified, and real-photo abstention is an accepted limitation rather than an open blocker. See the [design](../../openspec/changes/archive/2026-11-13-record-cu05-meter-readings/design.md).

## Scenario candidates

- **CU05-S01:** an unconfirmed entry does not enter history; an explicitly confirmed valid entry does, with or without a photo.
- **CU05-S02:** reject an unsupported or oversized photo; accept an allowed image subject to the reviewed safety policy.
- **CU05-S03:** show a warning for a later lower value but allow confirmation and saving.
- **CU05-S04:** allow same-day different-time readings; reject an exact normalized instant duplicate for the same meter while allowing it for another meter.
- **CU05-S05:** allow review/correction of a reliable OCR suggestion, or show the exact failure message and allow manual entry when OCR abstains.
- **CU05-S06:** protect readings and photos against other accounts; preserve photos across restart with the persistent volume.
