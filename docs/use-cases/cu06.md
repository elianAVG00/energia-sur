# CU06 - Record an electricity bill

- **Source / status:** P, CU06 in the [source key](README.md); IMPLEMENTED, VERIFIED
  and ARCHIVED on 2026-11-09 under the user-approved functional decisions. See the
  [archived change](../../openspec/changes/archive/2026-11-09-record-cu06-electricity-bills/proposal.md)
  and [main specification](../../openspec/specs/electricity-bills/spec.md). Shared
  [SR02](shared-rules.md#sr02---account-bound-personal-information),
  [SR04](shared-rules.md#sr04---user-supplied-personal-evidence) apply.
- **Actor:** account holder.
- **Preconditions:** personal address/meter association, authorized access,
  approved bill-period validation and file storage policy.

## Main flow

1. Actor selects address and meter.
2. Actor supplies billing period, billed kWh and a bill file.
3. Actor optionally supplies the amount.
4. System saves the bill linked to that address and meter.

## Alternatives

- No amount: the proposal allows this; it is not a required field.
- Identical period on the same meter is rejected; overlapping periods trigger a
  warning and can be saved after explicit confirmation. Invalid values/files are rejected.
- The owner can correct period, kWh, amount and replace the file with the same bill ID;
  no domicile/meter change or bill deletion is permitted.
- No tariff calculation, bill authenticity check or automatic extraction is added.

## Local rules and dependencies

- **CU06-R1 (P + user CU06 decisions):** start and end dates are required with start ≤ end;
  billed kWh is nonnegative with up to three decimals; one PDF/JPG/PNG up to 5 MB is
  required; optional ARS amount has up to two decimals. Owner-only access applies.
- Dependencies: CU04, auth/persistence and file policy; [Q03](decisions.md#q03),
  [Q09](decisions.md#q09), [Q12](decisions.md#q12), and CU07's period decision
  [Q13](decisions.md#q13); Q00.

## Verifiable scenario candidates

### CU06-S01 - Save bill with amount [IMPLEMENTED / VERIFIED]
**Trace:** CU06-R1; [SR02](shared-rules.md#sr02---account-bound-personal-information),
[SR04](shared-rules.md#sr04---user-supplied-personal-evidence).
**Given** an authorized synthetic meter/address and valid period/kWh/file/amount,
**When** the actor saves a bill, **Then** its fields and file are associated with
that address/meter. See Q12 for the confirmed decisions.

### CU06-S02 - Omit optional amount [IMPLEMENTED / VERIFIED]
**Trace:** CU06-R1.
**Given** otherwise valid bill input without an amount, **When** it is saved,
**Then** omission of amount alone does not prevent the bill from being recorded.

### CU06-S03 - Duplicate or invalid bill input [APPROVED RULE]
**Trace:** CU06-R1; [Q12](decisions.md#q12).
**Given** an identical period for the same meter or an invalid period/file,
**When** the actor submits it, **Then** it is rejected without mutation. A different
overlapping period warns and remains saveable after explicit confirmation.
