# CU06 - Record an electricity bill

- **Source / status:** P, CU06 in the [source key](README.md); PLANNED implementation,
  accepted U06 documentary baseline, not implemented. Shared [SR02](shared-rules.md#sr02---account-bound-personal-information),
  [SR04](shared-rules.md#sr04---user-supplied-personal-evidence) apply.
- **Actor:** account holder.
- **Preconditions:** personal address/meter association, authorized access,
  approved bill-period validation and file storage policy.

## Main flow

1. Actor selects address and meter.
2. Actor supplies billing period, billed kWh and a bill file.
3. Actor optionally supplies the amount.
4. System saves the bill linked to that address and meter.

## Alternatives

- No amount: the proposal allows this; it is not a required field.
- Duplicate, invalid period or unsupported file: policy TBD Q12.
- No tariff calculation, bill authenticity check or automatic extraction is added.

## Local rules and dependencies

- **CU06-R1 (P):** period, billed kWh and bill file are recorded against the personal
  address/meter; amount is optional.
- Dependencies: CU04, auth/persistence and file policy; [Q03](decisions.md#q03),
  [Q09](decisions.md#q09), [Q12](decisions.md#q12), and CU07's period decision
  [Q13](decisions.md#q13); Q00.

## Verifiable scenario candidates

### CU06-S01 - Save bill with amount [PLANNED]
**Trace:** CU06-R1; [SR02](shared-rules.md#sr02---account-bound-personal-information),
[SR04](shared-rules.md#sr04---user-supplied-personal-evidence).
**Given** an authorized synthetic meter/address and valid period/kWh/file/amount,
**When** the actor saves a bill, **Then** its fields and file are associated with
that address/meter. Exact field/file validation awaits Q12.

### CU06-S02 - Omit optional amount [PLANNED]
**Trace:** CU06-R1.
**Given** otherwise valid bill input without an amount, **When** it is saved,
**Then** omission of amount alone does not prevent the bill from being recorded.

### CU06-S03 - Duplicate or invalid bill input [BLOCKED/TBD]
**Trace:** CU06-R1; [Q12](decisions.md#q12).
**Given** a duplicate bill or invalid period/file under a future approved policy,
**When** the actor submits it, **Then** the outcome follows that policy. No exact
duplicate identity, file limit or correction behavior is currently approved.
