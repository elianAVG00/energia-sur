# CU03 - Get guidance from the integrated assistant

- **Source / status:** P, CU03 and product summary in the [source key](README.md);
  PLANNED implementation under the accepted U06 documentary baseline; not implemented. Shared [SR01](shared-rules.md#sr01---public-access),
  [SR03](shared-rules.md#sr03---provenance-and-uncertainty),
  [SR06](shared-rules.md#sr06---approval-and-delivery-boundary) apply.
- **Actor:** visitor or account holder.
- **Preconditions:** integrated backend assistant and approved official guides/data;
  provider setup and retrieval/citation behavior must be designed separately.

## Main flow

1. Actor asks about outages, scheduled works or consultation/complaint procedures.
2. Assistant uses relevant official guides and current public data.
3. Assistant gives guidance and identifies its sources, preserving uncertainty.

## Alternatives

- Missing/stale sources or unsupported question: U23 approves an identifiable static
  fallback/refusal; the exact Spanish copy remains a review detail.
- No complaint submission, private-record access, account administration or privileged
  MCP exposure is added by the guidance scope.

## Local rules and dependencies

- **CU03-R1 (P):** converse about outages, works and consultation/complaint procedures
  using official guidance/public information and cite sources.
- **CU03-R2 (C):** LangChain + OpenAI API runs in the backend direction; development
  MCP tools are not automatically runtime chat tools. Memory: temporary public and
  persistent authenticated, per U23.
- Dependencies: CU01/CU02/CU10 public-data capabilities, official guide selection,
  provider integration. [Q04](decisions.md#q04), [Q06](decisions.md#q06),
  [Q07](decisions.md#q07); Q00. No personal account prerequisite for public chat.

## Verifiable scenario candidates

### CU03-S01 - Grounded public guidance [PLANNED; guide delivered, revalidation pending]
**Trace:** CU03-R1/R2; [SR01](shared-rules.md#sr01---public-access),
[SR03](shared-rules.md#sr03---provenance-and-uncertainty).
**Given** a visitor and approved official guide/public-data fixtures, **When** the
visitor asks how to consult or complain about an outage, **Then** the integrated
assistant gives guidance grounded in those sources and identifies them without
requiring login. The approved guide is delivered (`document_id`
`energia-sur-kb-edesur-001`, version `1.0.0`, `2026-11-10`) and ingested at article
granularity; stale or incomplete items must be disclosed, not filled.

### CU03-S02 - Unsupported live claim [REVIEW; static fallback decided]
**Trace:** CU03-R1; [SR03](shared-rules.md#sr03---provenance-and-uncertainty),
[Q07](decisions.md#q07).
**Given** unavailable current public data, **When** asked whether service is currently
restored, **Then** the assistant does not invent a live status or fresh retrieval;
the static fallback/refusal is decided by U23 (Q07 CU03).

### CU03-S03 - No development privilege exposure [REVIEW]
**Trace:** CU03-R2; [SR06](shared-rules.md#sr06---approval-and-delivery-boundary).
**Given** a public chat request for a provider key or repository write, **When** the
assistant handles it, **Then** no key or privileged development-tool action is exposed.
This safety candidate does not authorize implementing new security policy here.
